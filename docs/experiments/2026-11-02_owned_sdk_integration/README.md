# 권선 명세와 소유 SDK 실행 경로 통합

기준: 2026-11-02 part84. 코드 통합 단계이며 새 소스의 실제 클러스터 검증·학습·최종 설계 인증은 아직 남아 있습니다.

## 문제 → 시도 → 확인된 개선

- 권선 변경이 전기각 보정·데이터 생성·학습·최적화의 고정 48턴 가정과 충돌했습니다. 별도 권선 명세와 생산 영점/좌표계 경로를 추가하고 기존 경로는 유지했습니다. 연구용 보정이나 테스트용 증거를 생산 자료로 승격하지 않습니다.
- 실행 전후 서로 다른 모델을 비교하면 같은 실행의 입력 유지 여부를 증명하기 어렵습니다. 동일 소유 SDK의 Analyze 전 저장 원본을 남기고 해석 후 저장 모델과 대조하는 경로를 추가했습니다. 저장 호출 직전 소유권/프로젝트를 재확인하고, 반환이 불명확하면 후속 Native 호출을 억제합니다.
- 실제 API는 command/env_setup 필드를 반환하지 않습니다. 관측 가능한 작업 식별자·노드·자원·중복 방지 키는 계속 대조하고, 명령 인자는 봉인한 최종 요청과 실행 전의 원래 worker argv/cwd/-I/-B로 별도 검증합니다. API에서 환경 문자열을 확인했다고 주장하지 않습니다.
- 노드별 FS 확인 → 설정 전용 Native0 → 실제 FEA smoke → 학습/설계 실행을 분리했습니다. 공유 예산·동시 작업 300개/노드당 12개·단계별 실제 예약·재제출 방지·원본 실패 보존을 연결했습니다.
- 최적화 예측 3회에서 원시 증거를 반복 읽던 666회 파일 열기를 0회로 줄였습니다. 탐색 시작/종료와 탐색 밖에서는 전체 파일 검사를 유지하며, 메모리 변조는 즉시, 파일 및 중첩 증거 변조는 종료 검사에서 거부했습니다. 실제 FEA 시간 단축 측정은 아닙니다.

## 검증과 남은 작업

봉인한 V3 641파일을 검토했습니다. 전체 검사에서 2,121개 통과·48개 건너뜀·35개 실패·8개 setup 오류를 확인했습니다. 기존 Git d8 원본의 대표 13사례에서도 11개 실패·2개 오류가 재현됐으며, 과거 실행자료 누락·고정 LF 해시·이전 실행기 의존성·구식 테스트 설정 등 6개 공통 원인으로 분류했습니다. 43개 실패 분기를 개별로 모두 재평가했다는 의미는 아닙니다.

현재 입력 명세의 117개 필드를 반영하고, 재료 오류 검사가 앞선 깊이 감사에 가려지던 pure stub을 보완한 두 테스트 파일은 12개 모두 통과했습니다. 별도의 직렬화 테스트는 현재 42필드 명세의 명시적 테스트 사례와, 3개 저장 설정이 없는 기존 39필드 원본의 거부를 각각 확인했습니다. 원시 fixture와 생산 검증기는 완화하지 않았습니다.
