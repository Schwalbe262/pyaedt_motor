The `public_owned_sdk_v1` backend is an explicit production route. Its original
row retains `analyze=True`, status, output values and Linux artifact paths. The
existing diagnostic profile remains restricted to n116 and its existing SDK
arguments. The owned CLI backend remains separate. No template enables a run.

Every SDK contract binds one unchanged CSV, physical/validator source records,
the complete launch runtime, node policy, six Root gates, purpose and case. The
runtime includes the existing immutable private SDK identity2a9, library23,
installation11, source commit, node and cores4. Root authority excludes its own
reference and the receipt from its subject hash. The case intent excludes only
the receipt; the final payload has its own SHA. The receipt binds the actual
contiguous shared-ledger snapshot and reserved stage. There is no circular hash.

Node admission is explicit:

1. An FS/import job uses `sdk_node_fs.py`, a separate Root FS authority and a
   fresh Linux3.11 `-I -B` process. It verifies the existing SDK1189, private
   imports, library and installation, actual node/UID1641 and own current Slurm4
   resources. It constructs no Native instance and consumes zero FEAs. Default
   invocation without `--capture-fs` performs no capture or file reads.
2. `node_native0` uses a positive FS observation, exact case/source authority and
   the original owned save/quit/gone/client-retirement receipt. It has no prior
   Native proof or FEA reservation. `render_native0_profile()` renders a HELD
   Native0 profile; the FEA controller explicitly refuses this mode.
3. `node_smoke` consumes one separately authorized diagnostic reservation. It
   requires the same-instance beforeimage, exact original AnalyzeTrue, full
   saved settings/semantics, original15s owned exit, saved native machine4 and
   matrix4, own ACF4 and original raw reports. These rows remain ineligible for
   training. Loaded smoke cases may support numerical profile certification.
4. Production requires same-source/runtime FS+Native0+FEA smoke on that node,
   actual frame/profile replay, six Root gates and a fresh training/design
   reservation. No wildcard, diagnostic relabel or Root boolean replaces proof.

For production, `run_ipmsm_batch.py` invokes the opt-in hook on the same owned

`SDKProductionController` routes a sealed plan through one shared host lock,
ledger and campaign. Each case has one explicit node/profile assignment. It
preserves global queued+active300 and per-node workers<=12, accounts for local
counter lag, and rechecks node capacity before reservation. It saves intent
before ledger append, renders the real receipt/snapshot/final profile after
reservation, seals the final payload, and persists POST uncertainty before the
socket. Resume verifies both identities and never blindly resubmits. Capacity
responses are not smoke evidence. Source18 packets are not accepted as new
source qualification through their source/producer mismatches.

`tools/run_owned_sdk_case.py` runs one isolated public case and publishes only
after original strict closure. Failed/unknown ownership permits controls only;
later PID absence cannot repair it. Publication retains raw/gzip/ASCII3SHA,
original paths, raw CSV, saved before/after, setup, state, profile/ACF, reports,
source and library. It is bounded by120 files,16MiB transport,4MiB per file and
256MiB decoded. Runtime still rehashes the existing SDK1189; per-case records
retain its verified identity instead of creating additional SDK file vectors.
Native binaries are observed by the actual FS/runtime checks, not copied into
result archives. `evidence_index_from_publication()` performs offline bounded
3SHA decoding and adds explicitly pinned Root task/binding/request and existing
qualification dependencies without rewriting any original row.

`OwnedSDKProductionEvidence.from_declaration(path, sha)` verifies actual files;
`verify_case(case_id, expected_producer=None)` replays source-derived variables,
setup/mesh/material/winding, saved semantics, original cleanup, current-Slurm
observation, original task/request and raw numerical definitions. The existing
loaded metric tolerances are unchanged. `verify_frame_rows` also binds every
original collected field and frame. `train_physical` accepts this backend only
through this typed evidence and actual training-stage receipt. Qualification,
design, missing, mixed or mutated evidence fails closed. Frame/profile/domain
admission calls the same verifier; copied passed flags cannot certify a profile.
