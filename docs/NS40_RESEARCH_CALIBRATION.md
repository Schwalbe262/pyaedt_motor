# Ns40 연구용 전기각 교정

기존 교정기는 상당 직렬48턴·코일당12턴만 받았습니다. 40턴·10턴 설계 후보는 설정과 해석을 생성할 수 있어도 이 교정 경로를 사용할 수 없었습니다. `research_ns40_zero.py`는 실제 두 속도 결과를 검증한 뒤 별도 연구용 영점을 계산합니다. 기본 교정기와 생산 DOE·기존 회귀모델의48턴 범위는 유지합니다.

흐름은 **M19/Ns40 무부하1200·5000rpm → 실제 저장 모델과 원시 결과행 검증 → signed Phase-A H1 영점 → 같은 형상의 부하 두 속도 직접 FEA**입니다. 현재 실제 Ns40 무부하 결과와 새 교정 ID는 아직 없으며, 코드 검사를 통과한 상태입니다. 기존 PNF 설계의59.8Nm나 다른 G1 형상의20.48Nm를 새 M19 후보 성능으로 사용하지 않습니다.

## 입력과 검증

명시적인 SHA로 고정한 `ns40_research_zero_evidence_v1` 계획에는 실제 두 결과행 CSV, 두 case 입력, 저장 AEDT·setup audit·solver-state marker, 원래 소스·라이브러리23파일·순수 파서·분석 코드의 해시와 재료 기준 파일을 연결합니다. 새로운 계획은 실제 실행이 끝난 뒤 그 원본 파일에서 구성합니다.

- 8극12슬롯·40/10턴·병렬1·전류0·β0·초기 영점0·빈 기존 교정 ID를 요구합니다.
- 동일17개 형상값, 깊이40~70mm, 직경300mm 이하, M19 B-H23점·실제 재료 할당·24개 독립 권선 단면과 실제 전류식을 대조합니다.
- 실제 Bool True 반환, 원래15초 기준의 소유 프로세스 종료·client 정리, 실제 깊이·시간·메시 설정과 저장 파일을 확인합니다.
- 실제 사용한 분석 helper의 경로·바이트도 대조합니다. 처음 읽은 파일의 권한을 새 해시로 바꾸거나 결과행을 필터링·재정렬하는 입력은 거부합니다.
- 기존 두 속도·최대3° 원형 편차 조건을 유지합니다. 결과 ID는 `research-ns40-zero:sha256:…`이며 기존48턴 ID 및 생산 교정 승인과 구분합니다.

## 실행

기본 호출은 파일을 읽거나 교정값을 발급하지 않습니다.

```powershell
python research_ns40_zero.py
python research_ns40_zero.py --analyze-research-ns40 --plan C:/study/actual_plan.json --plan-sha256 ACTUAL_PLAN_SHA256 --output C:/study/research_zero.json
```

실행과 원본 검증은 프로젝트의 기존 방식대로 C:의 native 작업 폴더나 실제 배포 파일시스템에 고정한 소스에서 수행합니다. Y: 작업공간에서는 JSON 파일의 strict realpath 검사가 제공자 제한으로 실패할 수 있어 경로 검사를 완화하지 않았습니다. 검증한 원래 소스를 같은 경로에서 불러올 수 있어야 합니다. 다른 배포 소스를 분석할 때는 분석 코드2파일을 별도 디렉터리에 고정하고 계획의 `source_root`·`validation_code`를 실제 파일에 맞춰 구성합니다. 이미 다른 소스의 helper가 로드된 프로세스는 허용하지 않습니다.

`apply_to_loaded_cases()`도 같은 원시 두 행을 다시 검증하고 형상·권선·재료·수치 설정·전기각 기준이 같은1200/5000rpm 부하 입력만 생성합니다. 해석 제출·예산 예약·생산 모델 승인은 수행하지 않습니다.

## 확인한 범위

별도 C 검토에서 실제 Ns40 설정 파일을 바탕으로 만든 **명시적 inert fixture**의 전체 파일 경로·CLI·manifest 재현·부하 입력까지7개 검사와 기존 교정기36개 검사를 통과했습니다. 이 fixture의 H1과 Solve 표시는 시험용이며 실제 FEA 증거가 아닙니다. 해당 큰 fixture 검사는 로컬 연구 아카이브에 보존했습니다.

저장소의 별도5개 검사는 기존48턴 범위 유지, 검증되지 않은 flag 거부, 최초 파일 해시 고정, 기본 실행과 기존 출력 보존을 확인하며 Ansys·로컬 연구 아카이브가 필요 없습니다. 실제 NoLoad 두 속도 교정과 부하 후보 성능은 후속 FEA로 확인합니다.
